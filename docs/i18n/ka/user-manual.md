## <a id="first-time-setup-manage-vehicles"></a>პირველად დაყენება: მანქანების მართვა

OCR და **მანქანის ავტომატური შესატყვისი** საუკეთესოდ მუშაობს მას შემდეგ, რაც თითოეულ მანქანას დაარეგისტრირებთ **საცნობარო დაფის ფოტოთი**, გაუშვით **Discovery**, დააყენეთ ოდომეტრის ამოღება პადლის თესლიდან და შეინახავთ ღირშესანიშნაობებს ამ ტირესთვის.

### <a id="open-manage-vehicles"></a>გახსენით სატრანსპორტო საშუალებების მართვა

მენიუ → **სატრანსპორტო საშუალებების მართვა**. აირჩიეთ მანქანა (ან ** ახალი ავტომობილის დამატება **).

![სატრანსპორტო საშუალებების მართვა საცნობარო ტირე, ნათესები და აღმოჩენები](https://raw.githubusercontent.com/davidelang/VehicleExpenses-Automated/master/docs/user-manual/images/r1-manage-vehicles-crops.jpg)

### <a id="add-or-edit-a-vehicle"></a>დაამატეთ ან შეცვალეთ მანქანა

1. გახსენით **Vehicle** ჩამოსაშლელი მენიუ → აირჩიეთ მანქანა ან **ახალი ავტომობილის დამატება**.
2. გადაიღეთ ან აირჩიეთ მკაფიო **საცნობარო ტირე ფოტო** (ინსტრუმენტების სრული ჯგუფი, კარგად განათებული, ტელეფონი დაახლოებით კვადრატში). გამოიყენეთ **ფოტოს გადაღება** ან **გალერეა**.
3. შეეხეთ **Run Discovery** — პანელის ამოცნობა ათავსებს ყვითელ **თესლებს** ფოტოზე (ღირშესანიშნაობებში გამოიყენება იგივე `"ML Kit"` JSON, როგორც ადრე).
4. შეეხეთ **აირჩიეთ Odo**, შეეხეთ თესლს ციფრებზე, შეცვალეთ სახელურები, შემდეგ **შენახვა**.
5. **Edit Odo** არეგულირებს ყუთს, რომელიც უკვე არსებობს. **Clear Odo** შლის მას და ღილაკი წაიკითხავს **Select Odo**.
6. მიმოხილვა **აჩვენე ღირსშესანიშნაობები**. გამოიყენეთ **Edit OCR** ​​არასწორი წაკითხვის გამოსასწორებლად ან **დაამატეთ** ტექსტი, რომელიც გამოტოვებულია.
7. შეავსეთ **მანქანის სახელი** (აუცილებელია), პლუს მარკა/მოდელი/წელი/ფირფიტი, როგორც გსურთ.
8. შეეხეთ **მანქანის შექმნა** ან **ცვლილებების შენახვას** (საჭიროა სახელი + საცნობარო ფოტო ახალი მანქანისთვის).

![მანქანის ახალი ფორმის ველების დამატება](https://raw.githubusercontent.com/davidelang/VehicleExpenses-Automated/master/docs/user-manual/images/03b-manage-vehicles-new.jpg)

### <a id="landmarks-fix-what-discovery-missed"></a>აღნიშნული ნიშნები: დააფიქსირეთ რა გამოტოვა Discovery

**მინიშნებების ჩვენების** შემდეგ გადაახვიეთ სიაში და შეასწორეთ მნიშვნელობები. ძრავებს ზოგჯერ გამოტოვებთ მცირე ციფრები (მაგალითად, საათი **60** კლასტერის ქვედა მარჯვენა მხარეს). გამოიყენეთ **Edit OCR** ​​მათი დასამატებლად ან გამოსასწორებლად, რათა ავტომობილის იდენტურობა საიმედო დარჩეს.

![Landmarks დიალოგი — გადახედეთ და შეცვალეთ OCR](https://raw.githubusercontent.com/davidelang/VehicleExpenses-Automated/master/docs/user-manual/images/r2-manage-vehicles-landmarks.jpg)

### <a id="typing-without-a-perfect-photo"></a> აკრეფა სრულყოფილი ფოტოს გარეშე

თქვენ კვლავ შეგიძლიათ გამოიყენოთ აპი მანქანის არჩევით და ** აკრიფეთ** ოდომეტრი, მოცულობა და ღირებულება Fill-ზე — OCR არჩევითია ყველა ველისთვის. გალერეის იმპორტი მუშაობს საცნობარო ტირე ფოტოზე, როცა გირჩევნიათ არ გადაიღოთ აპში.

**მინიშნება:** ცხრილების სინქრონიზაციის შემდეგ, მანქანების განმარტებები (კულტურები, ღირშესანიშნაობები) ცხოვრობს ადგილობრივ მონაცემთა ბაზაში — თქვენ არ გჭირდებათ ხელახლა გახსნა Manage Vehicles for Fill-ისთვის მათი გამოსაყენებლად.

## <a id="backups-and-multi-device-sync"></a>სარეზერვო ასლები და მრავალმოწყობილობის სინქრონიზაცია

აპი შექმნილია ისე, **რამდენიმე ტელეფონს ან ტაბლეტს შეეძლოს ერთი და იგივე ფლოტის მონაცემების გაზიარება** და ასე რომ თქვენ შეგიძლიათ შეინახოთ **თქვენი მონაცემებისა და ფოტოების ასლი მოწყობილობიდან**. ეს კეთდება მიმართულებებით **თქვენ** კონფიგურაციაში **თქვენი** ანგარიშების ან **თქვენი** თვითმმართველობის სერვერების ქვეშ — და არა კომპანიის მიერ გაშვებული „სატრანსპორტო ხარჯების ღრუბელი“, რომლის ნახვაც სხვა ადამიანებს შეუძლიათ.

### <a id="what-runs-where"></a>რა სად გადის

| კეთილი | რას ინახავს | ტიპიური გამოყენება |
|------|----------------|-------------|
| **ელცხრილი / ცხრილის სინქრონიზაცია ** | მანქანები, საწვავის შევსება, ხარჯები (სტრიქონები და ჩანართები) | მრავალი მოწყობილობის შერწყმა + სტრუქტურირებული სარეზერვო ასლი |
| **ფოტოს სარეზერვო ასლი** | ორობითი სურათები (ტირე / ტუმბო / ქვითარი / საცნობარო ფოტოები) | ფოტოების სარეზერვო ასლი + დაკარგული ფაილების აღდგენა |

შეგიძლიათ დააკონფიგურიროთ **მრავალჯერადი მიმართულება** თითოეული სახის (რბილი ქუდი თითო ტიპის). მექანიკური **სინქრონიზაცია ახლა** და **ფონში** მუშები აწარმოებენ ჩართულებს.

### <a id="offline-first"></a>პირველ რიგში ხაზგარეშე

- **არ არის საჭირო ქსელი** შევსების, ხარჯის ან ქვითრის დასამატებლად. ყველაფერი შენახულია ** ჯერ ადგილობრივად **.
- როდესაც ქსელი ხელმისაწვდომია, სინქრონიზაცია და ფოტოების სარეზერვო ასლი გადის **ფონური ამოცანების სახით** (თქვენ მიერ დაყენებული გრაფიკით და როდესაც დააჭირეთ **სინქრონიზაციას ახლა**). წარუმატებლობები გამოჩნდება წითელი ტექსტის სახით პარამეტრების სტრიქონებში და **!** აპის სათაურის ზოლში.

- წარუმატებლობები: წითელი შეჯამება სინქრონიზაციის ბარათებზე + **!** აპლიკაციის ზოლში.

### <a id="pump-mode-cost-and-volume"></a>ტუმბოს რეჟიმი (ღირებულება და მოცულობა)

1. შეეხეთ **↕** ტუმბოს რეჟიმზე გადასართავად: *მიზნად ტუმბოს ჩვენება (ღირებულება/მოცულობა). შეეხეთ ჩამკეტს.*
2. ტუმბოს ჯამების აღება. ღირებულებისა და მოცულობის ველების შევსება; გამოიყენეთ **↔**, თუ ისინი შეცვლილია.
3. საჭიროების შემთხვევაში შეეხეთ ვალუტას ან **G/L**, შემდეგ **Save** (დისკს). ცარიელი ველები ქმნის **ნაწილობრივ შევსებას** (ჯერ კიდევ ნებადართულია).

![შევსება — ტუმბოს გადახედვა / ჯამები (ტუმბოს სურათის მაგალითი გადახედვისას)](https://raw.githubusercontent.com/davidelang/VehicleExpenses-Automated/master/docs/user-manual/images/r5-fill-pump-result.jpg)

თქვენ დარჩებით Fill-ზე შემდეგი გაჩერებისთვის (ველები იწმინდება შენახვის შემდეგ). სრულად მუშაობა **ოფლაინ**; სინქრონიზაცია მოგვიანებით გადის ფონზე კონფიგურაციისას.

### <a id="manual-entry-no-camera--bad-ocr"></a>მექანიკური ჩანაწერი (კამერის გარეშე / ცუდი OCR)

1. შეეხეთ **Odo**, **cost**, ან **volume** და აკრიფეთ მნიშვნელობები (პორტრეტი იყენებს სისტემის კლავიატურას; ლანდშაფტი იყენებს ეკრანის კლავიატურას).
2. აირჩიეთ ან დაადასტურეთ **მანქანა**, თუ ავტომატური ამოცნობა არ მუშაობდა.
3. შეინახეთ როგორც ზემოთ.

### <a id="modes-and-borders"></a>რეჟიმები და საზღვრები

- **მწვანე საზღვარი** ავტომობილის გარშემო+ოდო → ოდომეტრის აღება/რედაქტირება.
- **მწვანე საზღვარი** ღირებულება+მოცულობის ირგვლივ → ტუმბოს რეჟიმი.
- **შენახვა** გათიშული რჩება მანამ, სანამ მანქანა არ აირჩევა და მინიმუმ ერთს ოდო/ფასი/მოცულობა ექნება მონაცემებს და OCR ჯერ კიდევ არ მუშაობს.

წვერი ეკრანზე (ინსტრუქციის ხაზის ქვემოთ): *ჩამკეტი = გადაღება · დისკი = შენახვა · ↕ = odo/ტუმბო რეჟიმი · ↔ = შეცვალეთ ღირებულება/მოცულობა.*

- **ჩამკეტის ხმის დაკვრა**
- **ვალუტა** / **მოცულობის ერთეული** — აპლიკაციის ნაგულისხმევი (სისტემა ან აშკარა). მოცულობის ერთეულის შეცვლა საწვავის არსებული მონაცემებით შეიძლება შემოგვთავაზოს კონვერტაციის დიალოგი.
- ** მუქი რეჟიმი **
- **დაყენების რჩევები** — ხელახლა გახსენით პირველი გაშვებული ავტომობილის / სინქრონიზაციის გაკვეთილები.
- **გამართვის შევსება** / **ექსპერიმენტის ეკრანების ჩვენება (dev)** — გაფართოებული; დატოვე ყოველდღიური გამოყენებისთვის. ექსპერიმენტის ეკრანები აქ არ არის დოკუმენტირებული.

CSV **ექსპორტი/იმპორტი** (სატრანსპორტო საშუალებების / ხარჯების / საწვავის ჩანართების ZIP) ხელმისაწვდომია პარამეტრებიდან, როდესაც გთავაზობთ მიმდინარე კონსტრუქციას.
