# In-app language packs (Play store-listing, left to right)

English is `values/` plus five English-variety packs: `values-b+en+001`, `values-en-rAU`, `values-en-rCA`, `values-en-rGB`, and `values-en-rIN`. Right-to-left packs are not shipped: `ar`, `fa` (including `fa-rAE`, `fa-rAF`, `fa-rIR`), `iw`, `ur`. The manifest keeps `android:supportsRtl="true"` and `android:label="${appLabel}"`. This commit does not turn on a right-to-left layout.

Indonesian is `values-in/` only. There is no `values-id/`. The pref tag is `id`. `AppLanguage` applies bcp47 `in` so Android resource matching hits `values-in`. A stored pref `pt-BR` selects `values-pt` (Brazilian text). `values-pt-rPT` stays European Portuguese. `ms-MY` is not a pack; Malay is `values-ms`.

## Pref

`app_language` in SharedPreferences `vehicle_settings` (`ui/util/AppLanguage.kt`).

| Pref value | Behavior |
|------------|----------|
| *(unset / first run)* | **English** |
| `en` | Force English |
| `system` | First system locale that matches a supported pack; else English |
| other supported tag | Force that pack |

Bare `pt` matches `pt-BR` (`values-pt`). `fil` matches `tl`. `no` matches `nb`. `nn` matches Nynorsk (`values-nn`). `in` matches `id`. Traditional Chinese (`zh-TW`, script Hant, or `zh-HK`) and Simplified (`zh-CN`) are separate packs. Serbian in Latin script matches `sr-Latn` (`values-b+sr+Latn`). `es-US`, `es-419`, `fr-CA`, and `pt-PT` match before the language-only pack. `ms-MY` is not a pack, so Malaysian Malay uses `values-ms`.

Apply: `AppLanguage.wrap` is what puts the locale on a `ComponentActivity` screen (a configuration context from `attachBaseContext`, and from `AppStrings.get`). `AppCompatDelegate.setApplicationLocales` remains the API 33 platform record, called from `VehicleExpensesApplication.onCreate` and from Settings when the pref changes.

## Supplied versus automated

A translation is automated unless a person has supplied one. Supplied text lives only in `docs/i18n/supplied/<prefTag>.xml`, one `<string name="...">` per override. This commit's supplied files have no entries. The packs still have a translation for every English key.

`./scripts/i18n_apply_supplied.py` (from the checkout root) writes supplied entries over the pack and drops keys that are gone from English `values/strings.xml` (from the pack and from the supplied file). Indonesian is `values-in` only. The script does not create `values-id` and does not translate. Run it after the automated text for a key is already in the pack.

Compare English `strings.xml` by key, not by the English sentence:

- Key removed: delete it from every pack and from the supplied file (the script does this).
- Key added: put automated text in every pack, unless that supplied file already names the key. Then run the script so the supplied line wins.
- Key kept, English unchanged: leave the pack text.
- Key kept, English changed: write a new automated translation only where no supplied entry exists. Where one exists, keep the supplied line.

`lang_name_*` stays the same endonym bytes in every pack. Do not treat an endonym edit as a translation.

These keys are storage or machine templates, not chrome. They stay the English source in every pack: `vehicle_ml_kit` (landmark JSON engine name `ML Kit`), `experiment_p4_1_s_2_s` (Netpbm header), `experiment_total_photos_1_s_results`, `experiment_device_1_s_kind_ocr_geom_total_photos_2_s`.

Keep these tokens in English whenever the English string contains them: `Hilt`, `Jetpack Compose`, `WorkManager`, `kotlinx-serialization`, `GitHub`, `ML Kit`, `Google Sign-In`, `EtherCalc`, `Zoho`, `OneDrive`, `SharePoint`, `OAuth`, `Paddle`, `OCR`, `VIN`, `CSV`, `PDF`, `JSON`, `GPS`, `EXIF`, `DNG`. The library token `Room` stays English only in `about_room_hilt_jetpack_compose_workmanager_google_sig` and `import_next_phase_rebuilds_from_room_after_your_a`. `settings_room_prefix` is an EtherCalc room and that word may be translated. Each `%1$s`-style format arg and each `\n` in the English value appears the same way in the translation.

Strings whose English matched the August `i18n_lang_packs` catalog keep that catalog's translation. The tag was not merged. Its manuals, screenshots, engineering log, and project-facts were not taken.

Romansh (`rm`, Rumantsch Grischun) is the German pack run through ZurichNLP `romansh-nllb-1.3b-ct2` (`rm-rumgr`). That model is CC-BY-NC-4.0. The weights are not in the repo. The other packs are machine translations, with the August catalog reused where the English key text is unchanged.

## Manuals

`docs/i18n/<pref>/user-manual.md` is a translation of the current `docs/user-manual/manual.md`. Image URLs still point at the English screenshots. Heading anchors stay the English ids (`<a id="..."></a>`), including `fill-up-fuel` and `help--about`. There is no `docs/i18n/in/` manual and no per-locale HTML or screenshots in this commit. The in-app reader still loads the bundled English HTML.

`docs/i18n/english-manual.sha256` is the hash of `docs/user-manual/manual.md` at generation. When that file changes, retranslate manuals that are not locked. `docs/i18n/supplied/manual-locks.txt` lists pref tags, one per line, whose `user-manual.md` a person has edited. Do not regenerate a locked manual. Record that the English manual changed. An English edit is not a new string key.

`AppLanguage.onlineManualHtmlUrl` points non-English locales at `docs/i18n/<tag>/user-manual.html` on jsDelivr. Those HTML files are not produced by this commit. Nothing in the app calls that helper yet. The WebView stays on the bundled English asset.

## Agent rules

1. Product chrome (Fill, Manage Vehicles, both drawer `MainActivity` copies, Help, Settings, experiment screens, and the other screens wired in this commit) uses `stringResource`, `context.getString`, or `AppStrings.get`. `AppStrings.install` runs in `Application.onCreate` immediately after `AppLanguage.applyFromPrefs`.
2. English `values/strings.xml` is the source of truth for keys. Add the key there first.
3. Domain-prefixed `snake_case` keys. Prefer `%1$s` format args. A pack must contain the same key set as English.
4. Do not localize: logcat; sheet and CSV column names; diagnostic email seeds (`DeviceFeedbackInfo`, fill-debug subjects and bodies); user-typed data; storage tokens (including the `ML Kit` landmark key); the Netpbm `P4` header. Pref values stored as codes (`system`, `on`, `off`, currency symbols such as `CA$`) stay codes. Only the labels are resources.
5. Units and money display stay on `VolumeUnits`, `UnitFormat`, and `CurrencyCodes`.
6. Do not add `values-ar`, `values-fa`, `values-iw`, or `values-ur`. The shipped English varieties are `values-b+en+001`, `values-en-rAU`, `values-en-rCA`, `values-en-rGB`, and `values-en-rIN`. Do not add further `values-en-r*` packs.
