**Pref:** `app_language` in SharedPreferences `vehicle_settings` (`ui/util/AppLanguage.kt`).

| Pref value | Behavior |
|------------|----------|
| *(unset / first run)* | **English** |
| `en` | Force English |
| `system` | First system locale matching a supported tag; else English |
| other supported tag | Force that pack |

Apply: `AppCompatDelegate.setApplicationLocales` from `VehicleExpensesApplication.onCreate` and on Settings change.

## Agent rules

1. **Product user-visible chrome** (except English-only surfaces below) must use `stringResource` / `context.getString` / plurals — **not** raw English literals in Kotlin.
2. **English `values/strings.xml` is source of truth** for keys. Add keys there first; regenerate non-en packs (AI translation is OK; owner English-only for validation).
3. Domain-prefixed `snake_case` keys (`nav_quick_fill`, `settings_language`, …). Prefer `%1$s` / `%d` format args.
4. **Do not localize:** logcat messages; sheet/CSV/protocol headers (single English header row); Import Old Pictures (`ui/import/**`); other `ui/experiment/**`; diagnostic email seeds (`DeviceFeedbackInfo`, `QuickFillDebugStore` subjects/bodies); user-typed data; seed trip/expense **storage tokens**.
5. Units/money display: still **`VolumeUnits` / `UnitFormat` / `CurrencyCodes` only** (see `UI_COMPATIBILITY.md`). Distance labels follow global `distance_unit` pref (mi/km wording only; no conversion).
6. **RTL / CJK / complex scripts:** deferred. Research: `dev-ai-interaction/research/i18n-rtl-and-beyond-languages-20260730.md`.
7. Spanish pack = **neutral Latin American** register in single `values-es/`.

## Tutorials

- Titles/bodies/CTAs: string resources (all supported locales).
- Images: **one shared set** under `app/src/main/assets/tutorials/` (not per-language).

## Full user manual (GitHub hosted)

- **Not** multi-locale inside the APK (optional English-only offline WebView assets may remain).
- English: `docs/user-manual.md` → `docs/user-manual.html` + `docs/user-manual/images/`.
- Other locales: `docs/i18n/<tag>/user-manual.md` → `.html` + `images/`.
- App: `UserManualDocs.openFullManual` opens **Custom Tabs / browser** to jsDelivr URL for active language (`AppLanguage.onlineManualHtmlUrl`); English URL if missing path.
- Screenshots: reshoot per language into that locale’s `images/` when UI is localized.
- Pipeline: `./scripts/render-user-manual.sh` (multi-locale) + `docs/reference/USER_MANUAL_BUILD.md`.
- End users: **HTML only**, never raw Markdown blob URLs.

## AI regen workflow

1. Finalize English keys in `values/strings.xml` and call sites.
2. Batch-translate every missing key into each `values-*/strings.xml` (Grok AI / MT acceptable; LatAm-neutral Spanish for `values-es`).
3. Translate Help/PageHelp/tutorial strings + `docs/i18n/<tag>/user-manual.md`.
4. Capture manual screenshots per language (or temporary English UI images with a note in `docs/i18n/README.md`); re-render HTML; commit so jsDelivr updates after publish.

## Completeness checks

- Every `values-*/strings.xml` must contain the same key set as English (Android falls back, but missing keys hide translation gaps).
- Import/experiment surfaces and sheet headers stay English by design.
- After adding product chrome strings, grep for residual literals outside `ui/import/**` and `ui/experiment/**`.
